# Server酱文章标题增加单篇解读链接设计

## 背景
- 当前 `Server酱` 批量通知在正文里按分组输出文章列表，格式为 `账号 | 时间 | 标题`。
- 现有通知末尾只提供统一的 `查看解读汇总` 链接，用户需要进入汇总页后再定位具体文章。
- 用户希望每篇文章标题直接带上“解读后的 URL”，并明确选择了“单篇解读页”语义。

## 目标
- 让 `Server酱` 批量通知中的每篇文章标题直接跳到对应文章的解读位置。
- 保持现有通知结构、汇总页入口和推送流程不变。
- 在缺少必要字段时优雅降级，避免因为单篇链接生成失败而阻断通知发送。

## 非目标
- 不新增独立的单篇 HTML 页面。
- 不改单篇 `Server酱` 通知的文案结构。
- 不改文章抓取、解读、缓存和推送状态逻辑。

## 范围
- 修改 `scripts/wechat_article_crawler/article_analysis.py`
  - 为账号页中的文章条目增加稳定锚点。
- 修改 `scripts/wechat_article_crawler/wechat_crawler.py`
  - 新增“单篇解读 URL”解析逻辑。
  - 将批量 `Server酱` 文章列表改为 markdown 链接。
- 修改 `tests/test_article_analysis.py`
  - 覆盖账号页锚点输出与批量通知链接输出。

## 方案概述

### 1. 账号页锚点
- 在账号页每篇文章的外层容器增加稳定锚点：
  - `id="article-<article_id>"`
- `article_id` 沿用现有归一化逻辑，不新增新字段、不修改现有 ID 生成规则。
- 这样生成后的账号页仍然是单个 HTML 文件，但每篇文章都可被直接深链访问。

### 2. 单篇解读 URL 生成
- 新增一个统一辅助函数，基于以下信息拼出单篇解读 URL：
  - `analysis_public_base_url`
  - 账号页相对路径
  - `article_id`
- URL 目标形式：
  - `https://<public-base>/article_analysis/accounts/<account-slug>.html#article-<article_id>`
- 若未配置 `analysis_public_base_url`，则沿用现有相对路径口径：
  - `/article_analysis/accounts/<account-slug>.html#article-<article_id>`

### 3. Server酱正文改造
- 仅改批量通知 `build_serverchan_markdown_articles(...)`。
- 文章列表从：
  - `- 账号 | 时间 | 标题`
- 改为：
  - `- 账号 | 时间 | [标题](单篇解读URL)`
- 末尾保留现有：
  - `查看解读汇总`
- 如果某篇文章无法生成单篇解读链接，则降级回原有纯文本标题，保证消息仍可正常发送。

## 详细行为

### 链接生成条件
- 满足以下条件时生成单篇解读链接：
  - 文章存在可归一化的 `article_id`
  - 文章存在可解析的账号名，用于映射账号页路径
- 任一条件不满足时：
  - 该篇文章仍然出现在通知中
  - 标题不带链接
  - 不抛异常，不影响其它文章和整体推送

### 页面结构兼容性
- 账号页当前每篇文章外层是 `.item` 容器。
- 给 `.item` 增加 `id` 不影响现有样式、按钮逻辑和重解读行为。
- 原有标题链接继续指向文章原文，不改成解读页链接，避免混淆页面内阅读路径。

### 通知可读性
- 保持现有分组标题和时间文本。
- 链接仅加在文章标题上，不给账号名和时间加链接，避免正文过度蓝化。
- 不在本次设计里增加“原文链接 / 解读链接”双链接，保持通知简洁。

## 风险与取舍

### 选择“账号页 + 锚点”而不是独立单篇页
- 优点：
  - 改动范围小
  - 复用现有静态页结构
  - 不需要新增单篇页面生成与索引逻辑
- 代价：
  - 链接 URL 稍长
  - 首次进入仍会加载整个账号页，而不是纯单篇页

### 锚点稳定性
- 只要 `article_id` 生成规则不变，锚点就稳定。
- 如果历史数据里个别文章缺失 `article_id`，这部分文章只会降级为纯文本，不会影响整体功能。

## 测试设计

### 自动化测试
- 在 `tests/test_article_analysis.py` 增加至少两类测试：
  - 账号页渲染测试：
    - 断言某篇文章外层容器带有 `id="article-<article_id>"`
  - `Server酱` 批量 markdown 测试：
    - 断言文章标题被渲染为指向单篇解读页锚点的 markdown 链接
    - 断言仍保留 `查看解读汇总`
    - 断言缺失 `article_id` 时降级为纯文本标题

### 手工验证
- 生成静态页后，打开一个账号页链接并带上锚点，确认浏览器可直接定位到目标文章。
- 触发或构造一次批量 `Server酱` markdown，确认标题链接格式正确。

  - `com.wechat.articlecrawler.analysis-static`

## 成功标准
- `Server酱` 批量通知中的每篇文章标题都尽可能指向对应单篇解读位置。
- 通知末尾继续保留汇总入口。
- 缺字段场景不报错、不影响推送。
- 账号页锚点和通知链接都有自动化测试覆盖。
